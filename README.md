# Compiler-derived-struct-offsets-for-assembly
a small repo that saves and restores CPU registers in assembly on an emulated ARM or RISC-V CPU (QEMU), with automated tests that show both that it works and that the safety checks can fail. The test is being performed on an local installed WSL (dist Ubuntu)
## M2: Offsets across targets
<img width="1386" height="628" alt="image" src="https://github.com/user-attachments/assets/9dbe647e-15f1-41a0-a4b8-d485425c9b62" />


Offsets depend on the struct and the target ABI. Fixed-width
fields give identical offsets on all targets; `unsigned long` and pointers
do not.

Method: `scripts/compare_targets.sh` cross-compiles the offsets file to
assembly (`gcc -S`) for x86-64, AArch64, RISC-V64 and 32-bit ARM, extracts
a header per target and compares them. No target code is executed.

Results:
| Struct | aarch64 vs host | riscv64 vs host | arm32 vs host |
|---|---|---|---|
| pt_regs (all uint32_t) | identical | identical | identical |
| probe (mixed types) | identical | identical | differs |

probe offsets (host / arm32): d 24 / 20, e 32 / 24, size 40 / 32;
a, b, c unchanged.

Conclusions:
1. Fixed-width fields gave identical offsets on every target tested.
2. `unsigned long` and pointers changed size on 32-bit ARM, and the
   offsets after them moved.
3. Structs shared with assembly should use fixed-width types, and the
   offsets must be generated by the target's own compiler.

Limits: one probe struct, four Linux GCC targets, not MSVC.
